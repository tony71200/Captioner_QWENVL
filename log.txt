2026-05-16 - Context overflow follow-up

New issue found
- GGUF caption generation could fail with: `Qwen3VLChatHandler(__call__): Critical Overflow. Not enough unpinned tokens to discard for Context Shift.`
- Root cause: the multimodal context window is overflowing. Large input images can produce a very high number of vision tokens, and together with the prompt text plus `max_new_tokens`, they can exceed the active GGUF context budget (`n_ctx`), especially on lower VRAM profiles.

Changes implemented
- Added image resize preprocessing for both `Single Image` and `Batch Processing`.
- Added two resize modes:
  - `Fit image`: force exact target width/height
  - `Adaptive image`: preserve aspect ratio, center on a black canvas
- Added configurable resize width and height controls in both tabs.
- Enforced resize dimensions as multiples of 32 in `utils/image_utils.py`.
- Batch processing now resizes each image into a temporary file before captioning, leaving the source images unchanged.
- Updated `run_independent_env.bat` so it deactivates the virtual environment after the server exits instead of leaving the shell active.

2026-05-16 - Performance tuning follow-up (ComfyUI-QwenVL parity pass)

New issue found
- Caption generation was still noticeably slower than the ComfyUI-QwenVL workflow.
- After comparing the local implementation against `1038lab/ComfyUI-QwenVL`, the biggest gaps were:
  - GGUF path still did extra Python-side image preprocessing overhead by converting each local image into a base64 data URI before inference.
  - GGUF llama.cpp runtime was using mostly default throughput settings instead of explicitly tuned `n_batch`, `n_ubatch`, CPU thread counts, and `offload_kqv`.
  - HF path did not explicitly enable cache-friendly runtime settings such as `model.config.use_cache = True`, `generation_config.use_cache = True`, `torch.inference_mode()`, or an explicit fast attention backend fallback (`sdpa`).

Changes implemented
- GGUF backend:
  - Switched local image handoff from base64 data URIs to `file://` URLs, which removes an extra encode/decode step per image and reduces CPU overhead during batch captioning.
  - Added llama.cpp runtime tuning in `captioner/gguf_captioner.py`:
    - `n_batch`
    - `n_ubatch`
    - `n_threads`
    - `n_threads_batch`
    - `use_mmap=True`
    - `offload_kqv=True`
    - `no_perf=True`
  - For `Qwen3VLChatHandler` / `Qwen25VLChatHandler`, disabled `add_vision_id` because this app captions one image at a time and does not benefit from numbering images in the prompt.
  - Kept `verbose=False` for the handler to reduce console churn.
- HuggingFace backend:
  - Added `low_cpu_mem_usage=True` during model load.
  - Added a CUDA runtime tuning helper that enables high matmul precision and TF32 where supported.
  - If Flash Attention is not explicitly enabled, the backend now prefers `sdpa` on CUDA instead of leaving attention backend selection implicit.
  - Enabled cache usage explicitly on the model and generation config.
  - Switched generation guard from `torch.no_grad()` to `torch.inference_mode()`.
  - Passed `use_cache=True` into `generate()`.
- Help text:
  - Updated the troubleshooting note to explain that image size and low GGUF GPU layer counts are the biggest practical causes of slow generation, and that `Adaptive image` at `768x768` or lower is a good default for low VRAM.

Files changed in this follow-up
- `captioner/gguf_captioner.py`
- `captioner/hf_captioner.py`
- `app.py`
